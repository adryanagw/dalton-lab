## 2. Key decisions and why

- **Content split principle:** entire static/non-interactive content (tables, definition lists, long reference material, worked-example dumps) moves OUT of the HTML chapter page and into a PDF companion, written in full prose/formula detail — not summarized. Interactive elements (toggles, accordions, calculators, exercise gates, quizzes, diagrams+3D-embeds with their direct explanation) stay in HTML. This is now documented as the core principle in `CHAPTER_CONTENT_GUIDE.md`.
- **Never invent embeds/citations.** Only real, user-supplied Sketchfab URLs were embedded (Biologi has 7 3D models — all from URLs the user pasted). No 3D models or images were invented for Matematika; its PDF path leans on LaTeX/KaTeX-typeset derivations instead, per the guide's per-subject rules.
- **Analogy discipline.** A running complaint this session: chapter prose over-relied on a single analogy (e.g. "sel = kota kecil") carried literally into nearly every sentence and card ("pagar", "pos satpam", "kantor pos", "bayar tol", etc.), reading as over-styled rather than informative. Fixed everywhere it appeared in Biologi (Membran Sel, Organel Sel, Transpor Membran, Sitoskeleton). Rule now in the guide: **state an analogy once for orientation, then describe the real thing directly using its real name** — never let the analogy's vocabulary replace the actual terminology throughout a section.
- **Rendering pipeline fix.** The old PDF-page render method (a fixed-viewport CLI screenshot: `chrome --headless=new --window-size=794,1123 --screenshot=... file://<temp-one-page-doc>.html`) is fragile — its captured viewport can silently mismatch the page's actual laid-out height if the temp doc's body isn't margin/padding-free. Replaced with a **Playwright element-screenshot** approach: load the whole filled `.pdf-pages.html`, select all `.pdf-page` elements, screenshot each one directly. This captures each page's own box regardless of anything before/after it — much more robust. Documented in the guide as the new standard method.
- **Overflow verification must be measured, not eyeballed.** Established (and then proved necessary twice — once on Biologi, once on Matematika) that every `.pdf-pages.html` page must be checked via actual DOM measurement (`.page-body.scrollHeight` vs `.clientHeight` in headless Chromium), not just a visual glance at the rendered PNG — dense pages can silently clip content in a way that's easy to miss at a glance. When a page overflows by a small margin, fix it with a `dense` page-body modifier class (tighter paragraph/callout spacing, scoped to just that page) rather than cutting content or changing the shared font size.
- **PDF companion font size.** Body text was bumped ~10–15% (e.g. body-text 13.5–14.5px → 15px, lead 15–15.5px → 16.5px, lists 14.5px → 16px, callouts 13–13.5px → 14.5px) across Ekonomi, Biologi, and the shared `page-template.html` reference, after the user found the original PDF text too small to read comfortably. All 22 existing pages (10 Biologi + 12 Ekonomi) plus the new 10 Matematika pages were re-rendered and re-verified for overflow after this change.
- **Merge policy changed mid-session.** Originally: never merge a PR without the user explicitly typing "merge". The user then said **"always auto merge"** — from that point on, every PR was merged automatically as soon as its Vercel preview deployment came back Ready (this repo has no other CI). This preference should carry forward into any future session unless the user says otherwise.
- **Never write documentation/planning files unless asked** — this file is an explicit exception since the user asked for it directly.

## 4. Unfinished / possible next steps

- **Fisika and Kimia have no PDF companions yet** — only Ekonomi, Biologi, and Matematika Bab 1 do. If those subjects get bab1 chapters built, they should follow the same guide.
- **The PDF-viewer "border cut off at the bottom" bug is mitigated, not proven fixed.** Extensive headless-Chromium investigation this session traced it to a genuine browser-level image-paint race (reproducible with a plain `<img>` and even a `<canvas>` redraw, independent of CSS overflow/border-radius/object-fit, and flaky rather than deterministic) — it is NOT a CSS/markup bug on our side. Added the standard defensive mitigation (`img.decode()` + forced reflow before reveal, `decoding="sync"`) in `initPdfViewers()`, but this cannot be guaranteed to eliminate a browser-level race. **If a student reports it again, a page reload clears it immediately** (it's a one-time paint glitch, not bad/missing data) — worth relaying that to users if it recurs, and worth revisiting if it turns out to still be frequent in the wild.
- **A large, separate "Dalton Lab Design System" redesign plan exists** at `/root/.claude/plans/fizzy-moseying-blum.md` (from an earlier plan-mode session) — a full visual redesign proposal for the web shell (navbar, home page, sign-in page, component consolidation, icon system, etc.), explicitly scoped to NOT touch chapter content. It was not executed in this session (this session's work was entirely chapter-content-focused). Worth checking whether the user still wants to pursue it.
- **Matematika's redesign was produced by a subagent** (`dalton-chapter-writer`) and then independently verified (tag balance, overflow measurement, math correctness spot-checks, watermark-free check) before merging — but it's worth a first-hand read-through in a future session if any doubts come up, since it wasn't hand-written turn-by-turn the way Ekonomi/Biologi were.
